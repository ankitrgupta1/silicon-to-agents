# Pathways

The repo is organized by layer of the stack, from hardware up. Learning rarely goes in that order, so pathways give you routes through the same pages.

| Path | For | Outcome |
|---|---|---|
| [Fundamentals](fundamentals.md) | New to ML | You can explain and code a tiny GPT, and build a basic RAG app |
| [Builder](builder.md) | App and agent builders | You can build, evaluate and cost an agent, and know what happens underneath |
| [Practitioner](practitioner.md) | Deep internals | You can train, optimize, distribute and serve a model, then wrap it in an agent |

Each pathway also has a machine-readable manifest (`*.yml` in this folder) that lists topic IDs in order. Topic pages declare which pathways they belong to in their front-matter.

Steps marked *planned* don't have a page yet; they link to their layer overview.
